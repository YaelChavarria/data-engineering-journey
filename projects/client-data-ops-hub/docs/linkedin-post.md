# Recruiter-facing LinkedIn Post

```text
Some companies do not need another dashboard.

They need someone to take ownership of the data work behind it.

That is the idea behind my new project: Client Data Operations Hub.

I designed it as a blueprint for a managed data service that a company could outsource to a trusted data partner.

The workflow is intentionally practical:

- The client provides agreed exports
- We validate them against a data contract
- Critical quality issues block publication
- We transform the data into business-ready deliverables
- We provide a scorecard, account health view and daily operations table
- We attach quality evidence, SLA status and a recovery path

The simulated client is a North American SaaS company. The project tracks recurring revenue, collections, overdue invoices, account health and support performance.

I also documented the part that is often missing from technical projects:

- Discovery and acceptance criteria
- Client onboarding
- Responsibility boundaries
- Service catalogue
- Security expectations
- Incident handling
- Delivery sign-off

The goal is simple: the client should not have to manage every data task internally to trust its numbers.

This is a local, reproducible case study using synthetic data. It demonstrates how I would take a data engagement from intake to delivery and ongoing operations.
```
