# Recruiter-facing LinkedIn Post

```text
Most data projects answer: “What happened?”

I wanted to build one that answers:

“Where are we losing revenue, and what should Operations prioritize today?”

I built a Revenue Protection Data Platform for a simulated North American e-commerce company.

The platform:

- Ingests orders, payments, shipments and refunds
- Calculates gross revenue, refunds, net revenue and operational leakage
- Detects late-delivery exposure and groups leakage by cause
- Uses typed Medallion layers and incremental dbt models
- Applies referential integrity checks and automated data tests
- Serves Finance and Operations through a Streamlit control tower

I managed the project end to end:

- Defined the business problem and acceptance criteria
- Prioritized the MVP
- Designed the data architecture and contract
- Documented assumptions, trade-offs and failure recovery
- Added CI so the project is reproducible for every change

Measured project evidence:

- 7 source entities
- 9 Gold models
- 23 dbt data tests
- 209 generated source records
- approximately 16 seconds for a full local run

Stack: Python, DuckDB, Parquet, dbt, Streamlit, Docker and GitHub Actions.

This is a simulated case study using deterministic synthetic data. It is designed to demonstrate the path from a business requirement to a tested, decision-ready data product.
```
