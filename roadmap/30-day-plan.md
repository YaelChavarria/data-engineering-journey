# Plan de 30 días

## Propósito

Crear una base práctica para trabajar como Data Engineer y terminar con al menos un proyecto público, reproducible y explicable.

Este documento es un plan de aprendizaje personal. No representa una promesa de alcanzar un nivel profesional concreto en 30 días.

## Bloques

| Bloque | Temas | Entregable |
|---|---|---|
| 1. Cloud y almacenamiento | Azure Storage, AWS S3, GCP, Terraform | Ingesta de un dataset público |
| 2. Procesamiento y modelado | PySpark, particionamiento, Kimball, dbt | Transformación validada |
| 3. Operación de pipelines | Airflow, streaming, calidad, CI/CD | Pipeline automatizado |
| 4. Portafolio | Capstone, documentación y entrevistas | Repositorio público reproducible |

## Stack objetivo

- Python, SQL y Git.
- Docker.
- Azure, AWS y GCP a nivel práctico.
- Snowflake o Databricks según disponibilidad.
- PySpark.
- dbt.
- Airflow.
- Great Expectations o Soda.
- Kafka como complemento.

## Reglas de trabajo

1. Cada tema debe terminar en una evidencia: código, consulta, diagrama o nota técnica.
2. No publicar credenciales ni datos privados.
3. Probar el proyecto desde un clon limpio antes de presentarlo.
4. Documentar qué funciona, qué no funciona y qué queda pendiente.
5. Priorizar fundamentos y proyectos terminados sobre acumular herramientas.

## Hitos

- Hito 1: entorno local preparado.
- Hito 2: primer pipeline local.
- Hito 3: pipeline con almacenamiento cloud.
- Hito 4: procesamiento y validación de datos.
- Hito 5: capstone documentado y publicado.
